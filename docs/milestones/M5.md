## 3. Code-Flow Walkthroughs

### Walkthrough 1: Ticking a Task on Today
1. **User interaction:** The user presses `X` on a focused task or clicks the checkbox in `TaskItem.tsx` (`src/components/board/TaskItem.tsx`).
2. **Client mutation:** `useBoard()` executes optimistic toggle: the checkbox flips immediately and strikes through the title. It dispatches a `PATCH /api/tasks/[id]` request with `{ done: true }`.
3. **Route handler:** `src/app/api/tasks/[id]/route.ts` receives the request, calls `requireOwner(req)` to authenticate the Supabase cookie session, and unpacks `Ctx`.
4. **Service execution:** `toggleTaskDone(ctx, id)` in `src/lib/services/tasks.ts` executes:
   - Updates `tasks` table: sets `done = true`, `completed_at = now()`.
   - If the task has a `tracker_item_id`, it automatically updates `tracker_items` setting `completed_at = now()`, keeping the linked tracker in sync.
5. **Response & SWR revalidation:** The endpoint responds with `200 OK` and the updated task record. SWR updates cache state and refreshes rail counters.

### Walkthrough 2: Agent `add_task` Call via `/api/mcp`
1. **Agent HTTP POST:** The AI agent (e.g. Antigravity or Muse) issues an HTTP POST to `https://life.rhrony05.me/api/mcp` with header `Authorization: Bearer ld_...` and JSON-RPC body invoking `add_task` with `{ title: "Review CS402 lab report", day: "today" }`.
2. **Stateless Auth:** `src/app/api/mcp/route.ts` passes the header to `requireAgent(authHeader)` in `src/lib/agent/auth.ts`:
   - Validates key format (`looksLikeKey`).
   - Computes `SHA-256(token)`.
   - Queries `api_keys` for `key_hash` where `revoked_at IS NULL`.
   - Updates `last_used_at` asynchronously.
   - Constructs `Ctx` with actor `{ type: "agent", keyId, name, scopes }`.
3. **McpServer Binding & Transport:**
   - Instantiates a per-request `McpServer({ name: "life-dashboard" })`.
   - `registerToolsForAgent(server, ctx)` only registers tools permitted by the key's scopes (`tasks:write` permits `add_task`).
   - Attaches `WebStandardStreamableHTTPServerTransport({ sessionIdGenerator: undefined, enableJsonResponse: true })`.
4. **Tool Execution & Rate Limit:**
   - `runTool()` in `src/lib/agent/run-tool.ts` checks rolling rate limits in `agent_audit` (<30 calls/minute).
   - Validates args against `AddTaskSchema` (Zod).
   - Calls the exact same service function `createTask(ctx, { title, day })` in `src/lib/services/tasks.ts`.
   - Records an immutable audit row in `agent_audit` with `result: "ok"` and latency.
5. **Response out:** Returns standard JSON-RPC response with tool content to the agent.

### Walkthrough 3: Daily Reminder Email Cron Job
1. **Trigger:** Vercel Cron fires `GET /api/cron/daily` at 02:00 UTC (08:00 AM Asia/Dhaka) with header `Authorization: Bearer <CRON_SECRET>`.
2. **Cron handler:** `src/app/api/cron/daily/route.ts` verifies the bearer token against `process.env.CRON_SECRET`.
3. **Renewal Calculation:**
   - Calls `getRenewalsDue(ctx, todayStr)` in `src/lib/services/renewals.ts`.
   - Identifies active renewals matching target reminder stages ($d = 7, 1, 0, -1, 20$).
   - Filters out renewals that have already received an email for that specific `(renewal_id, renews_on, stage)` using `reminder_log`.
4. **Email Dispatch:**
   - If reminders are due, constructs a Swiss Ink HTML digest email.
   - Dispatches via nodemailer using Gmail SMTP (`GMAIL_USER` and `GMAIL_APP_PASSWORD`).
   - Inserts records into `reminder_log` to guarantee idempotency.
5. **Log Retention:**
   - Deletes all `agent_audit` records older than 90 days (`now() - interval '90 days'`).
   - Responds with `200 OK` and a summary of sent reminders and pruned logs.
