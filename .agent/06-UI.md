# 06 — UI behaviour

**What it looks like is decided in [design/](design/README.md)**: tokens and every screen, desktop
and mobile. This file covers behaviour and where each piece of data comes from. If the two disagree
on looks, the design wins; on behaviour, this file wins.

The app is desktop-first (check at **1440×900**) and must also work at **390×844**. Light/dark
follows the system. Dates are shown in `APP_TIMEZONE` like "Mon 2 Nov" (the year only when it isn't
the current year). Money is shown with `formatTaka` (07 §3); USD as `$20.00`.

## Shell (design: every screen)
- Sticky Topbar: `AppHeader` (desktop) and `MobileHeader` (mobile) are sticky (`sticky top-0 z-40 bg-surface border-b border-frame`), remaining persistently accessible at the top while scrolling long pages like Canvas, Money, or Today.
- Desktop (≥ 768 px) `AppHeader`: `Logo` + "Life Dashboard" · nav **Today · Canvas · Trackers · Money · Renewals · Settings** · today's date ("Mon 2 Nov") · `ThemeToggle` (light default with local storage persistence) · keyboard button (opens the shortcuts dialog) · avatar "R" (menu: **Log out**).
- Nav badges: **Renewals** shows the number of `overdue + due_soon` (warn colour; danger when any is overdue), hidden when 0. Nothing else has a badge.
- Mobile (< 768 px): `MobileHeader` (page title + `ThemeToggle` + page actions) and a bottom `TabBar` with the same 6 items (icons: `calendar-check`, `clipboard-paste`, `list-checks`, `wallet`, `refresh-cw`, `settings`).
- Navigation: instant optimistic tab switching with a 2px accent progress line; route loading skeletons for all top-level sections (`(app)/loading.tsx`, `canvas/loading.tsx`, etc.).
- Dialogs: scroll-safe with `max-height: calc(100dvh - 2rem)` and `overflow-y: auto`. `EntryDialog` uses a compact 2-column grid (`row2`) for Amount and Date to fit standard viewports.
- Every mutation: optimistic where noted, otherwise a busy state on the control. Success → `router.refresh()`. Failure → toast "Couldn't save. Try again." with **Retry**, and the optimistic change is rolled back.

## `/login` (design: D01, M01)
Email, password, **Sign in**. Wrong credentials → danger banner "Wrong email or password." No sign-up, no reset. A logged-in visitor is sent to `/`.

## `/` — Today (design: D02, M02)
### Desktop (≥ 1024 px): three day columns + right rail (≥ 1280 px; between 1024 and 1279 the rail moves below the columns)
- Column headers: "Yesterday · Sun 1 Nov", "**Today** · Mon 2 Nov" (accent), "Tomorrow · Tue 3 Nov". Each header has "3 of 7 done" on the right (hidden at 0 tasks).
- **Today** and **Tomorrow** start with an inline `TaskInput` ("Add a task…", Enter adds, Esc clears). Today's input is autofocused on page load (desktop only). **Yesterday has no input.**
- `TaskRow`: checkbox · title (note shown as a second muted line, max 2 lines) · badges (`moved 2×` when `movedCount ≥ 2`; `via Muse` when `createdBy ≠ "owner"`; `NeetCode 150` tracker chip when linked) · on hover/focus a quick move button (`arrow-right` "Move to tomorrow" / `arrow-left` "Move to today", per `moveTargets`) and a `⋯` menu (**Move to today / Move to tomorrow** per `moveTargets`, **Edit**, **Delete**).
- Ticking is **optimistic**: the row strikes through and drops below the open rows (200 ms) with no reload.
- Moving is **optimistic**: the row leaves its column and is appended to the target. Toast "Moved to Today" with **Undo** (Undo moves it back with another PATCH; `moved_count` stays incremented, which is accepted).
- Edit: the row turns into title + note inputs; Enter or blur saves, Esc cancels.
- Delete: confirm dialog "Delete “Submit CN lab report”?" [Cancel] [Delete].
- Yesterday footer: if it has open tasks, or there are older unfinished ones, show the **Move all unfinished to today (N)** button (N = yesterday open + older). It is not optimistic: show a busy state, then toast "Moved N tasks to Today".
- "Older unfinished · N" (collapsible, collapsed by default, remembered in `localStorage`) at the bottom of Yesterday; each row shows its date ("Thu 29 Oct").
- Empty columns: Yesterday "Nothing was planned for yesterday."; Today "Nothing planned yet. Add the first task above."; Tomorrow "Plan ahead: add something for tomorrow."
- **Rollover (B8):** a client timer fires at `msUntilNextMidnight` (+2 s) and calls `GET /api/board`, then rebuilds the columns. Also refetch on `visibilitychange` → visible when the board's `today` differs from the client's computed today, or when more than 5 minutes have passed since the last fetch.

## `/canvas` (design: D08, D08b, M09, M10)
Two places, one editor. **Scratch** lives in this browser (IndexedDB) and is never sent anywhere.
**Pages** (the `notes` table) are saved in the database. Both use the same editor (`src/lib/canvas/editor.ts`).
Canvas v2 (V3c–V3d, design D08b, M10, M11) adds sub-pages, tabs, folding, pins and agent edits; see "Canvas v2" below. D08b's pane replaces D08's notes list.

### Desktop (≥ 1024 px): notes pane (280 px) + editor
- Left pane, top: the **Scratch** card (selected = accent-soft), with the line "Only in this browser". Below: "NOTES · 12", a search input (filters as you type, 200 ms debounce, `GET /api/notes?q=`) and the note rows (title, snippet, relative date, "via Muse" badge when `createdBy ≠ owner`). The open row is selected.
- Editor card (max text width 760 px, centred): head = title (Scratch: the fixed label "SCRATCH"; a note: an editable title input, saved on blur/Enter, empty → previous title) · save status · actions. Scratch actions: **Copy as Markdown** (primary), **Save as note** (secondary), `⋯` → **Clear Scratch**. Note actions: **Copy as Markdown**, `⋯` → **Copy to Scratch** (appends), **Delete note**.
- Toolbar under the head: H1 · H2 · H3 | Bold · Italic · Strike · Inline code | Bullet list · Numbered list · Checklist | Quote · Code block | Link · Image (file picker). Each shows its active state; tooltips name the shortcut. Markdown typing works too (`## `, `- `, `[ ] `, ```` ``` ````, `> `).
- Body: the TipTap editor. Opening `/canvas` focuses Scratch with the cursor at the end. Clicking anywhere on the whitespace focuses the editor at the end (`min-height: 500px`, `caret-color: var(--ink)`). ### Behaviour
- **Paste** follows 07 §8.2 exactly. `Ctrl+Shift+V` always pastes plain text.
- **Copy**: selection `Ctrl+C` writes HTML **and** plain text (07 §8.3b); `Ctrl+Shift+C` copies the selection as Markdown. **Copy as Markdown** (`Ctrl+Alt+M`) copies the whole page → toast "Copied as Markdown · 42 lines".
- **Images**: pasted, dropped or picked files go through 07 §8.1. Scratch: stored in IndexedDB at once. Note: shown at once from the local file with an "Uploading…" overlay, then `POST /api/notes/[id]/images` swaps in the `sb:` ref. Upload fails → the image is removed and a toast offers **Retry**.
- **Scratch saving**: 500 ms after the last change, and on `visibilitychange` (hidden) and `pagehide`. Status text: "Saved · this browser". `navigator.storage.persist()` is requested once.
- **Clear Scratch**: no dialog; the doc is emptied, toast "Scratch cleared" + **Undo** (10 s). Images are only deleted from IndexedDB when the toast ends.
- **One tab owns Scratch** (Web Locks, 07 §8.6). Another tab shows Scratch read-only with the banner "Scratch is open in another tab." + **Use here**.
- **Save as note** (07 §8.7) → the new note goes to the top of the list (not opened); toast "Saved as "CN questions"" with **Open** and **Clear Scratch**.
- **Note saving**: 800 ms after the last change (`PATCH` with `baseUpdatedAt`). Status: "Saving…" → "Saved". Failure → "Couldn't save · Retry" (danger text, auto-retry after 2 s, 5 s, 10 s) and a `beforeunload` warning while unsaved. Saves go through the per-page queue (07 §8.9), so your own typing never conflicts; a real change from elsewhere is handled as in "Canvas v2" → Saving and conflicts.
- **Delete note**: confirm dialog "Delete "CN questions"? Its images are deleted too." → toast "Note deleted" (no undo).
- A note with `doc = null` (made or edited by an agent) is built from `bodyMd` **parsed as Markdown** (`setContent(md, { contentType: "markdown" })`) when it opens.

### Canvas v2 (V3c–V3d; design D08b, M10)
**Pages pane (desktop, 280 px):** Scratch card · **New page** (secondary, `Ctrl+Alt+N`) · search · "PINNED" group (only when something is pinned) · "PAGES · 12" tree. Tree rows: chevron (only when the page has sub-pages; expanded state in `localStorage`), title, `via Muse` badge when an agent created it; indent 16 px per level; on hover `+` (new sub-page) and `⋯` (**New sub-page**, **Pin / Unpin**, **Move to…**, **Delete**). The page open in the active tab is selected. Search shows flat result rows with the path as the snippet line ("DevTools / Backend tips"). Siblings A–Z. New page / sub-page → created as "Untitled", opened in a new tab, title selected.
**Move to…** dialog: a page picker (the tree, without the page itself and its sub-pages) + "Top level"; pages that would make it deeper than 3 levels are disabled with the hint "Max 3 levels".
**Delete** confirm: "Delete "DevTools" and its 3 sub-pages? Their images are deleted too." (the sub-page part only when it has some).

**Tab bar** (above the editor card, full editor width): tab 1 = **Scratch** (icon `clipboard-paste`, no close), then open pages (title, max 24 chars with `…`, `×` on hover and on the active tab, middle-click closes). Max **8** page tabs: opening a 9th closes the least recently used tab that isn't active (its save is flushed first). Opening a page (tree, search, breadcrumb, Sub-pages list, toast **Open**) focuses its tab if open, else adds a tab after the active one. State `{ open: id[], active }` in `localStorage` key `life-canvas-tabs-<userId>`; ids that no longer exist are dropped on load. Each tab keeps its scroll position and selection while the page is open. Switching tabs flushes the pending save of the tab you leave. One TipTap editor is reused; content is swapped with `emitUpdate: false`.

**Editor head (page):** breadcrumb above the title ("DevTools › Backend tips", each part opens that page; hidden for top-level pages) · title input · save status · actions (**Copy as Markdown**, `⋯` → New sub-page, Pin / Unpin, Move to…, Copy to Scratch, Delete). After an agent edit (`prevBy` set): a line under the title "Edited by Muse · 5m ago · **Undo**" (Undo → confirm "Undo Muse's edit? Changes you made after it are lost too." → `POST …/undo-agent-edit` → toast "Muse's edit undone").
**Sub-pages list** under the page text (only for pages at depth 1–2): label "SUB-PAGES", one row per child (title + relative date) and **+ New sub-page**. It is UI only, not part of the doc or `body_md`.
**Folding:** a chevron left of every H1–H3 (visible on hover, always visible when folded). Folding hides the blocks below it until the next heading of the same or higher level, using ProseMirror decorations (the doc never changes). State per page in `localStorage` (`life-canvas-folds-<pageId>` = heading texts with their index). Copy as Markdown and agents always get everything.
**Saving and conflicts (replaces the 409 banner):** saves follow the queue in 07 §8.9, so your own typing never conflicts. When the page changed on the server (an agent, or another device): no unsaved edits → load it silently, toast "DevTools was updated by Muse"; unsaved edits → a warn line in the editor head "Muse changed this page while you were typing. **See theirs** · **Keep mine**" (Keep mine saves yours on top of theirs; See theirs drops your unsaved typing). No full-width banner.
**Copy & Export:** `Ctrl+C` = HTML + plain text (07 §8.3b). Images in range selections (e.g. `Ctrl+A`) visibly highlight with `.cimg.sel` outline and tint; HTML clipboard serializes `<img src="..." data-ref="...">` with valid data/hosted URLs. **Export as PDF** (button in header, menu, and `Ctrl+P`): uses `@media print` styles hiding UI chrome and headers, adding `.print-only-header` with title and date. `Ctrl+Shift+C` = selection as Markdown → toast "Copied as Markdown". Sticky navbar (`AppHeader` / `MobileHeader` `sticky top-0 z-40`) keeps navigation accessible on long scrolling pages.
**Mobile:** the segmented control is "Scratch · Pages". Pages = search + Pinned + the tree (M10, same rows, 44 px). An open page shows its breadcrumb under the `MobileHeader`; the header's title button "DevTools ▾" lists the open tabs (Scratch first) to switch, with `×` per tab. Sub-pages list and folding work the same.
