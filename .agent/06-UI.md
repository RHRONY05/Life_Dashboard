# 06 — UI behaviour

**What it looks like is decided in [design/](design/README.md)**: tokens and every screen, desktop
and mobile. This file covers behaviour and where each piece of data comes from. If the two disagree
on looks, the design wins; on behaviour, this file wins.

The app is desktop-first (check at **1440×900**) and must also work at **390×844**. Light/dark
follows the system. Dates are shown in `APP_TIMEZONE` like "Mon 2 Nov" (the year only when it isn't
the current year). Money is shown with `formatTaka` (07 §3); USD as `$20.00`.

## Shell (design: every screen)
- Desktop (≥ 768 px) `AppHeader`: `Logo` + "Life Dashboard" · nav **Today · Canvas · Trackers · Money · Renewals · Settings** · today's date ("Mon 2 Nov") · keyboard button (opens the shortcuts dialog) · avatar "R" (menu: **Log out**).
- Nav badges: **Renewals** shows the number of `overdue + due_soon` (warn colour; danger when any is overdue), hidden when 0. Nothing else has a badge.
- Mobile (< 768 px): `MobileHeader` (page title + page actions) and a bottom `TabBar` with the same 6 items (icons: `calendar-check`, `clipboard-paste`, `list-checks`, `wallet`, `refresh-cw`, `settings`).
- Every mutation: optimistic where noted, otherwise a busy state on the control. Success → `router.refresh()`. Failure → toast "Couldn't save. Try again." with **Retry**, and the optimistic change is rolled back.

## `/login` (design: D01, M01)
Email, password, **Sign in**. Wrong credentials → danger banner "Wrong email or password." No sign-up, no reset. A logged-in visitor is sent to `/`.

## `/` — Today (design: D02, M02)
### Desktop (≥ 1024 px): three day columns + right rail (≥ 1280 px; between 1024 and 1279 the rail moves below the columns)
- Column headers: "Yesterday · Sun 1 Nov", "**Today** · Mon 2 Nov" (accent), "Tomorrow · Tue 3 Nov". Each header has "3 of 7 done" on the right (hidden at 0 tasks).
- **Today** and **Tomorrow** start with an inline `TaskInput` ("Add a task…", Enter adds, Esc clears). Today's input is autofocused on page load (desktop only). **Yesterday has no input.**
- `TaskRow`: checkbox · title (note shown as a second muted line, max 2 lines) · badges (`moved 2×` when `movedCount ≥ 2`; `via Muse` when `createdBy ≠ "owner"`; `NeetCode 150` tracker chip when linked) · on hover/focus a quick move button (`arrow-right` "Move to tomorrow" / `arrow-left` "Move to today", per `moveTargets`) and a `⋯` menu (**Move to today / Move to tomorrow** per `moveTargets`, **Edit**, **Delete**).
- Ticking is **optimistic**: the row strikes through and drops below the open rows (200 ms) with no reload.
- Moving is **optimistic**: the row leaves its column and is appended to the target. Toast "Moved to Today" with **Undo** (Undo moves it back with another PATCH; `moved_count` stays incremented, which is accepted).
- Edit: the row turns into title + note inputs; Enter or blur saves, Esc cancels.
- Delete: confirm dialog "Delete “Submit CN lab report”?" [Cancel] [Delete].
- Yesterday footer: if it has open tasks, or there are older unfinished ones, show the **Move all unfinished to today (N)** button (N = yesterday open + older). It is not optimistic: show a busy state, then toast "Moved N tasks to Today".
- "Older unfinished · N" (collapsible, collapsed by default, remembered in `localStorage`) at the bottom of Yesterday; each row shows its date ("Thu 29 Oct").
- Empty columns: Yesterday "Nothing was planned for yesterday."; Today "Nothing planned yet. Add the first task above."; Tomorrow "Plan ahead: add something for tomorrow."
- **Rollover (B8):** a client timer fires at `msUntilNextMidnight` (+2 s) and calls `GET /api/board`, then rebuilds the columns. Also refetch on `visibilitychange` → visible when the board's `today` differs from the client's computed today, or when more than 5 minutes have passed since the last fetch.

### Lists (`ListsSection`, under the three columns, same width as the columns; design: D02, M08)
Rony's own undated sections, like Notion: he creates and manages them; nothing in them ever moves by itself.
- Header row: "LISTS" label · **New list** button (inline input appears as the last card; Enter creates, Esc cancels).
- Cards in a 3-column grid (same column widths as the day columns; 2 columns at 1024–1279 px), in `position` order. Each `ListCard`:
  - Title (uppercase like the day columns) · open count · collapse chevron · `⋯` menu: **Rename** (inline), **Move left / Move right** (`Alt+←/→` when the card is focused; = `reorder: "up" / "down"` in the API), **Clear done**, **Delete list** (confirm "Delete “To do later” and its 5 items?").
  - `TaskInput` "Add to To do later…" at the top. Rows are the same `TaskRow` as the board (badges included), with a menu: **Plan for today**, **Plan for tomorrow**, **Move to list →** (other lists), **Move up / down** (`Alt+↑/↓`), **Edit**, **Delete**.
  - Done items: collapsed "Done · N" line at the bottom of the card (expand to see them, struck through). **Clear done** deletes them (confirm "Delete 3 done items?").
- Board `TaskRow` menus get **Move to list →** with every list (hidden when there are no lists).
- Empty (no lists): `lists-empty` illustration (small, inline) + "Keep things that don't belong to a day here." + three suggestion chips: **To do later**, **This week's targets**, **This month's targets** (one click creates that list) + **New list**. These are suggestions only, never auto-created.
- Planning an item for today: optimistic; the row leaves the list and appears at the end of Today; toast "Planned for today" + Undo (moves it back into the same list).

### Right rail (`TodayRail`, 320 px)
1. **Quick links** (`LinkGrid`): 2-column tiles with icon + title, opening in a new tab (`rel="noopener"`). "Edit" → `/settings#links`. Empty: "Add links to your other tools in Settings."
2. **Coming up** (`UpcomingRenewals`): active renewals with `daysLeft ≤ 14` or overdue, at most 4, by date: name, `dueLabel` badge, amount. "All renewals →". Empty: "Nothing renews in the next 2 weeks."
3. **Money** (`MoneySummary`): "Spent today ৳160" and the month line with a small `BudgetBar` ("৳730 of ৳8,000"), then "Others owe you ৳1,250" (success text) · "You owe ৳600" (danger text). "Open Money →". Each half is hidden when it has no data; the block is hidden when both are empty.
4. **Trackers** (`TrackerProgress`): each non-archived tracker (max 4): name, `ProgressBar`, "52 / 150". Click → `/trackers?id=…`. Hidden when there are none.

### Mobile (< 1024 px for the columns)
- `DaySwitcher` segmented control: **Yesterday · Today · Tomorrow · Lists**, default Today. "Lists" shows the list cards stacked full width (design M08). Swiping left/right on the list switches days too. Badge counts of open tasks on each segment.
- One column at a time, same rows. The quick move is in the row's `⋯` menu (no hover on touch). The task input sits at the top of Today/Tomorrow.
- Below the list: a horizontal `LinkStrip` (chips) and the **Coming up** card (max 3). The Money and Trackers rail blocks are not shown on mobile Today.

## `/canvas` (design: D08, M09, M10)
Two places, one editor. **Scratch** lives in this browser (IndexedDB) and is never sent anywhere.
**Notes** are saved in the database. Both use the same editor (`src/lib/canvas/editor.ts`).

### Desktop (≥ 1024 px): notes pane (280 px) + editor
- Left pane, top: the **Scratch** card (selected = accent-soft), with the line "Only in this browser". Below: "NOTES · 12", a search input (filters as you type, 200 ms debounce, `GET /api/notes?q=`) and the note rows (title, snippet, relative date, "via Muse" badge when `createdBy ≠ owner`). The open row is selected.
- Editor card (max text width 760 px, centred): head = title (Scratch: the fixed label "SCRATCH"; a note: an editable title input, saved on blur/Enter, empty → previous title) · save status · actions. Scratch actions: **Copy as Markdown** (primary), **Save as note** (secondary), `⋯` → **Clear Scratch**. Note actions: **Copy as Markdown**, `⋯` → **Copy to Scratch** (appends), **Delete note**.
- Toolbar under the head: H1 · H2 · H3 | Bold · Italic · Strike · Inline code | Bullet list · Numbered list · Checklist | Quote · Code block | Link · Image (file picker). Each shows its active state; tooltips name the shortcut. Markdown typing works too (`## `, `- `, `[ ] `, ```` ``` ````, `> `).
- Body: the TipTap editor. Opening `/canvas` focuses Scratch with the cursor at the end. `Ctrl+S` = Save as note (Scratch) / save now (note); the browser's own save dialog never opens.
- Between 768 and 1023 px: the pane collapses to a "Scratch · Notes" `Segmented` above the editor (same as mobile).

### Mobile (< 768 px)
- `MobileHeader`: title "Canvas", actions **Copy** (icon `copy`) and `⋯` (Save as note, Clear Scratch / Copy to Scratch, Delete note).
- A `Segmented` "Scratch · Notes" under the header. Scratch shows the editor. Notes shows the search + note list (M10); tapping a note opens it full width with a back arrow and its title in the header.
- The toolbar is one row that scrolls sideways, sticky under the segmented control.

### Behaviour
- **Paste** follows 07 §8.2 exactly. `Ctrl+Shift+V` always pastes plain text.
- **Copy**: selection `Ctrl+C` writes HTML **and** Markdown as `text/plain` (07 §8.3). **Copy as Markdown** (`Ctrl+Alt+M`) copies the whole page → toast "Copied as Markdown · 42 lines".
- **Images**: pasted, dropped or picked files go through 07 §8.1. Scratch: stored in IndexedDB at once. Note: shown at once from the local file with an "Uploading…" overlay, then `POST /api/notes/[id]/images` swaps in the `sb:` ref. Upload fails → the image is removed and a toast offers **Retry**.
- **Scratch saving**: 500 ms after the last change, and on `visibilitychange` (hidden) and `pagehide`. Status text: "Saved · this browser". `navigator.storage.persist()` is requested once.
- **Clear Scratch**: no dialog; the doc is emptied, toast "Scratch cleared" + **Undo** (10 s). Images are only deleted from IndexedDB when the toast ends.
- **One tab owns Scratch** (Web Locks, 07 §8.6). Another tab shows Scratch read-only with the banner "Scratch is open in another tab." + **Use here**.
- **Save as note** (07 §8.7) → the new note goes to the top of the list (not opened); toast "Saved as "CN questions"" with **Open** and **Clear Scratch**.
- **Note saving**: 800 ms after the last change (`PATCH` with `baseUpdatedAt`). Status: "Saving…" → "Saved". Failure → "Couldn't save · Retry" (danger text, auto-retry after 2 s, 5 s, 10 s) and a `beforeunload` warning while unsaved. 409 `stale` → banner "This note changed somewhere else." **Load latest** · **Keep mine** (Keep mine re-sends with the server's `updatedAt`).
- **Delete note**: confirm dialog "Delete "CN questions"? Its images are deleted too." → toast "Note deleted" (no undo).
- A note with `doc = null` (made by an agent) is built from `bodyMd` when it opens.

## `/trackers` (design: D03, M03)
- Desktop ≥ 1024 px: list pane (340 px) + detail pane. `?id=` selects a tracker (default: the most recently updated). Below 1024 px: the list only, and tapping opens `/trackers/[id]`.
- List: `TrackerCard` per tracker (name, description line, `ProgressBar`, "52 / 150 · 35%", `via Muse` badge if an agent created it). **New tracker** button → dialog: name, description, a big textarea "Items (optional) — one per line; `## Group` starts a group; add ` | url` for a link", with a live "N items" count from the parser. "Archived (N)" toggle at the bottom.
- Detail: title, description, progress, a menu (**Rename**, **Archive / Unarchive**, **Delete**: confirm "Delete “NeetCode 150” and its 150 items?"). Filter segmented control **All · To do · Done** (default To do). Groups as sections with "Arrays & Hashing · 6 / 9".
- `ItemRow`: checkbox (todo ⇄ done, optimistic) · title (a link icon when `url` is set, opening in a new tab) · `scheduledOn` chip ("On board · Today") · `⋯` menu (**Add to today**, **Add to tomorrow**, **Skip / Unskip**, **Edit**, **Delete**). Skipped rows are muted with a "skipped" chip and are shown under "All".
- "Add items" at the bottom of the detail → an inline textarea (paste format) + **Add**.
- Empty (no trackers): illustration-free empty state "Make a list you want to work through: a problem set, a reading list, a course." + **New tracker**.

## `/money` — two tabs: **Spending** (default) · **IOUs**
A `Segmented` control under the page title switches tabs; the URL is `/money` (Spending) or `/money?tab=ious`. The `a` shortcut opens the add form of the current tab.

### Spending tab (design: D04, M04)
- `SpendTiles`: **Today** · **This week** (sub-line "Sat 31 Oct – Fri 6 Nov") · **This month** with the `BudgetBar` ("৳730 of ৳8,000 · ৳7,270 left"; warn at ≥ 80 %, danger + "৳X over budget" above 100 %). Without a budget the month tile shows "Set a monthly budget" (link → small dialog with one amount field and **Save** / **Remove budget**). Clicking the budget line opens the same dialog.
- `QuickSpend` (always visible above the list): amount field with `৳` prefix (autofocused on desktop), 8 category chips (single choice, icon + label, remembers the last used category in `localStorage`), note field, date (default "Today"; a small date picker for the past), **Add** (Enter). After saving: the row appears at the top of Today's group, tiles update from the returned `summary`, the amount and note clear, focus returns to the amount. Toast "Added ৳120 · Food".
- `CategoryBars` (desktop: right column 360 px; mobile: under the tiles, collapsible "Where it went"): this month's categories, icon + label + amount + bar (width = pct) + pct.
- `SpendList`: groups by day ("Today · ৳160", "Yesterday · ৳570", "Sat 31 Oct · ৳210"), rows: category icon · note (or the category label if no note) · `via Muse` badge · amount · `⋯` (**Edit** → same form in a dialog, **Delete** → confirm "Delete ৳120 · Food?"). **Load more** at the bottom.
- Empty (no expenses ever): illustration `spend-empty`, "Track where your money goes. One line per spend.", focus the amount field.

### IOUs tab (design: D07, M07)
- Top `MoneyTotals`: three tiles: **Others owe you** ৳ (success), **You owe** ৳ (danger), **Net** ("you're owed ৳700" / "you owe ৳300" / "all settled").
- **Add entry** button (also `a`) → `EntryDialog`: person (text input with autocomplete from existing people), kind as 4-way segmented control **I lent · I borrowed · They paid me · I paid them**, amount (numeric, "৳" prefix, whole numbers), note, date (default today). Submit → toast "Saved: Rahim owes you ৳300 now" (the new balance sentence).
- People list (`PersonRow`): name · balance sentence ("owes you ৳300" / "you owe ৳600" / "settled") · last entry date · **Settle** button (hidden when settled) → confirm "Mark Rahim as settled? This records ‘Rahim paid you ৳300’." Settled people are under a "Settled (N)" divider.
- Person menu (`⋯` in the history pane header; on mobile in the expanded row): **Rename**, **Delete** (confirm "Delete Karim and their 4 entries?").
- Desktop ≥ 1024 px: clicking a person opens the history pane on the right (`EntryList`: date, kind phrase "You lent ৳500", note, `via Muse`, delete icon with confirm). Mobile: the row expands in place to show the history.
- Empty: "Write down who owes whom. It takes five seconds." + **Add entry**.

## `/renewals` (design: D05, M05)
- Header: **Add renewal** (also `a`), segmented control **Active · Ended**, and monthly totals "≈ ৳1,450 / month · $21.00 / month".
- Banner when anything is overdue: danger "2 overdue: mark them renewed or ended."
- Active list grouped as **Overdue**, **Next 30 days**, **Later**, **No date** (free items without a date). `RenewalRow`: category icon (`repeat` subscription, `server` hosting, `globe` domain, `gift` credit) · name + project chip · `actionLine` · amount + cycle ("$20 / month", "$12 / year", "free", "one-time ৳500") · `dueLabel` badge (danger overdue, warn due_soon, neutral upcoming) · buttons **Renewed** (only monthly/yearly, it advances the date with toast "Next: Sat 12 Dec" and Undo, which PATCHes the old date back) and `⋯` (**Edit**, **Mark ended**, **Open manage page** if `manageUrl`, **Delete**).
- `RenewalDialog` (add/edit): name, category (segmented), project, cost (amount + BDT/USD toggle; empty = unknown, 0 = free), cycle (segmented **Monthly · Yearly · One-time · Free**), next date ("Renews / ends on"; required unless Free), "It charges me automatically" switch (`autoRenew`), remind me (select: 0, 1, 3, 7, 14, 30 days before; default 7), manage URL, notes.
- Empty: "Add the things that end or charge you: subscriptions, hosting, domains, student credits." + **Add renewal**.

## `/settings` (design: D06, M06): one page, four sections with anchors
1. **Agents** `#agents`: an explainer line "Agents connect to `<APP_URL>/api/mcp` with their own key." with a copy button. Table (`KeyTable`): name · prefix `ld_AbCd1234…` (mono) · scope chips (`tasks rw`, `money r` …: one chip per module, `rw` when write is granted) · last used ("4 min ago" / "never") · created · **Revoke** (confirm "Revoke Muse's key? Muse loses access immediately."). Revoked keys: greyed, "revoked 3 Nov", no button. **New key** → `KeyDialog`:
   - Step 1: name (with the suggestions Muse / Antigravity / Claude Code as chips, which also pre-fill the scopes from 05 §7), a scope grid (rows tasks/trackers/money/renewals/links; columns Read/Write; the links row has no Write), **Create key**.
   - Step 2 (show once): warn banner "Copy this key now. You won't see it again." · the key in a mono field with **Copy** · tabs **Antigravity · Claude Code · Other** with the snippets from 05 §7 already containing the key, each with **Copy** · **Done**. Closing step 2 by any means shows a confirm "Did you copy the key?" [Back] [Yes, close].
2. **Activity** `#activity`: `AuditTable` with the latest 50 rows: time ("10:42", or "Sun 1 Nov 22:00" if not today) · agent · summary (mono tool name + text) · result chip (ok success / denied warn / error danger / rate limited warn) · duration. Filter by agent (select). **Load more**. Empty: "No agent activity yet."
3. **Quick links** `#links`: list (icon, title, url) with edit/delete, and **Add link** (title, url, icon picker from the 10 allowed icons). Max 12 (button disabled with a hint at 12).
4. **Email reminders** `#email`: "Reminders go to `REMINDER_TO` every morning around 08:00 when something renews or ends." · **Send test email** → "Sent. Check your inbox." / danger "Couldn't send. Check GMAIL_APP_PASSWORD." 

## Keyboard shortcuts (desktop; listed in the shortcuts dialog, opened with `?`)
| Key | Where | Action |
|---|---|---|
| `n` | Today | Focus Today's task input |
| `Shift+N` | Today | Focus Tomorrow's task input |
| `j` / `k` | Today, tracker detail | Move focus to the next / previous row |
| `x` | focused row | Toggle done |
| `m` | focused task | Move to the first entry of `moveTargets` |
| `Alt+↑` / `Alt+↓` | focused list item | Move up / down in its list |
| `Alt+←` / `Alt+→` | focused list card | Move the list left / right |
| `l` | Today | Focus the first list's input |
| `e` | focused task / item | Edit |
| `a` | Money, Renewals | Focus the spend amount (Spending) / Add entry (IOUs) / Add renewal |
| `g` then `t` / `c` / `r` / `m` / `w` / `s` | anywhere | Go to Today / Canvas / tRackers / Money / reneWals / Settings |
| `Ctrl+Alt+M` | Canvas | Copy the page as Markdown |
| `Ctrl+S` | Canvas | Scratch: Save as note · Note: save now |
| `Ctrl+Shift+V` | Canvas editor | Paste as plain text |
| `Esc` | Canvas editor | Leave the editor (so single-key shortcuts work) |
| `?` | anywhere | Shortcuts dialog |
| `Esc` | dialogs, inputs | Close / cancel |
Shortcuts are ignored while typing in an input or the Canvas editor (except `Esc` and the `Ctrl` shortcuts above). `kbd` hints are hidden on touch devices.
