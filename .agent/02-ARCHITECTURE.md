## Auth
### The human (owner)
- Supabase email + password. The user **already exists** in project `vocab` (created by Vocab). Sign-ups are already disabled there; V0 confirms it.
- `proxy.ts`: refresh the session; every page except `/login` needs a session, else redirect to `/login`. Excluded from the redirect: `/api/mcp` (key auth) and `/api/cron/daily` (secret auth). API routes return 401 instead of redirecting.
- Every owner route calls `requireOwner()` (`src/lib/auth.ts`): no session, or `email !== ALLOWED_EMAIL` → 401. It returns an **owner context** (below).
- RLS limits every row to `(select auth.uid()) = user_id`.

### Agents
- `Authorization: Bearer ld_…` on `/api/mcp` only. `requireAgent()` (`src/lib/agent/auth.ts`) hashes the key, finds an active (not revoked) row in `api_keys`, checks the rate limit, and returns an **agent context** whose `userId` is the key row's `user_id`. Full rules are in `05-MCP-AND-KEYS.md`.

## Two front doors, one service layer
```
Browser (Rony)                                    Agent (Muse / Antigravity / Claude Code)
  │ fetch /api/tasks … (cookie session)              │ POST /api/mcp  (Bearer ld_…, JSON-RPC)
  ▼                                                  ▼
route handler                                      mcp route (mcp-handler, stateless)
  requireOwner() → ctx {db: RLS client,              requireAgent() → ctx {db: service-role client,
                        userId, actor: owner}                              userId, actor: agent{keyId,name,scopes}}
  Zod-parse body                                     tool registered only if key has its scope
  │                                                  Zod-parse tool input (same schema)
  └──────────────► src/lib/services/*.ts ◄───────────┘
                   assertScope(ctx, "tasks:write")   ← no-op for owner, enforced for agents
                   every query: .eq("user_id", ctx.userId); inserts set user_id explicitly
                   pure rules from src/lib/domain/*  (dates, board, money, renewals)
                   ▼
                 Supabase Postgres
  ◄── JSON ──────── result ──────────► MCP tool result (JSON text + structuredContent)
                                       + agent_audit row (ok / denied / error / rate_limited)
```
Rules that make this safe:
- `src/lib/supabase/admin.ts` (service-role client) may be imported **only** from `src/lib/agent/**`, `src/app/api/mcp/**`, `src/app/api/cron/**`, `scripts/**` and `tests/**`. Enforce with ESLint `no-restricted-imports` + an override for those paths. It starts with `import "server-only"`.
- Services never trust RLS alone: they always filter by `ctx.userId` (the RLS client does the same thing again, which is fine).
- Pages are Server Components that call services directly with the owner context. Client components mutate through `/api/*` routes and then call `router.refresh()`.

## Deploy (Vercel MCP)
- Private GitHub repo `RHRONY05/Life_Dashboard`, push `main`.
- V2 creates the Vercel project `life-dashboard` from the repo, sets the env vars above and deploys. Domain: add `life.rhrony05.me` the same way `vocab.rhrony05.me` was added for Vocab (check that project's domain setup and record it). If DNS can't be done through MCP, add a human step with the exact record and use `life-rony.vercel.app` until then.
- `vercel.json` cron: `{"path": "/api/cron/daily", "schedule": "0 2 * * *"}` (02:00 UTC = 08:00 Dhaka; Hobby runs it once a day, somewhere within that hour). Vercel sends `Authorization: Bearer <CRON_SECRET>`.
- From V2 on, **every task ends with a deploy** and a quick check on the production URL (the task's AC says what).
- MCP route config: `export const runtime = "nodejs"`, `maxDuration = 30`.
